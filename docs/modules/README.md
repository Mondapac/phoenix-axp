# ماژول‌ها — دروازه‌های آمادگی (ADR-0013)

پیش از طراحی و کدنویسی هر ماژول کلیدی، کلیات و امکانات آن با صاحب پروژه و نقش‌های مرتبط مرور و تأیید می‌شود. هر ماژول یک «برگهٔ ماژول» دارد: `docs/modules/<module>/brief.md` (قالب: [`_template/brief.md`](_template/brief.md)). روال: skill `phoenix-module-gate`.

**رابطه با مرور فاز:** هیچ ماژولی پیش از تأیید مرور فازِ خودش (`docs/phases/phase-<n>-review.md`) وارد دروازه‌ها نمی‌شود. مرور فاز کل فاز را تأیید می‌کند؛ G1 و G2 هر ماژول داخل همان فاز انجام می‌شوند.

## جریان کار هر ماژول
```
مرور فاز تأییدشده
  → برگهٔ ماژول (هادی پیش‌نویس می‌کند)
  → G1 دامنه و امکانات (صاحب پروژه + هادی + علی [+ جعفر])    ← تصمیم‌ها یکی‌یکی با کارت
  → طراحی (محمد، مجتبی، رضا و جعفر)
  → G2 طراحی (محمد + علی + مجتبی [+ رضا + حسن])              ← خلاصه و تصمیم‌های لازم
  → برش‌های کد → CI → بازبینی ترکیبی QA+QC → امنیت (مسیرهای حساس)
```

- **Definition of Ready:** بدون G1 طراحی شروع نمی‌شود؛ بدون G2 (یا دروازهٔ ترکیبی برای سطح B) کدی نوشته نمی‌شود.
- **تغییر در حین کدنویسی:** کار متوقف می‌شود، یک مرور کوچک انجام و در «تاریخچهٔ تغییرات» برگه ثبت می‌شود.
- **تمرکز بر تصمیم:** دروازه برای گرفتن تصمیم است، نه مستندنویسی کامل؛ تصمیم‌های برگشت‌پذیر عمداً به بعد موکول می‌شوند.
- **speed mode:** فقط ماژول‌های سطح A برگهٔ کامل و دو دروازه دارند؛ اسناد کوتاه و بخش‌بخش.

## سطح‌بندی

| سطح | دروازه‌ها | ماژول‌ها |
|---|---|---|
| **A** | G1 + G2 + بازبینی امنیتی | identity/authz، tenancy (Tenant، Site، Organization)، process (BPM و پل Flowable)، objects، forms |
| **B** | یک دروازهٔ ترکیبی | portal، pages (صفحه‌ساز)، sites، notifications، search، media، commerce |
| **C** | فقط تأیید product-owner | reporting و قابلیت‌های P2 به بعد که روی مجوز، دادهٔ شخصی یا فرایند اثر ندارند |

`platform/` (از جمله `platform/ai` و `platform/audit`) کد پلتفرم است، نه ماژول: با تأیید علی و، در مسیرهای حساس، بازبینی حسن پذیرفته می‌شود (ADR-0010، ADR-0011).
